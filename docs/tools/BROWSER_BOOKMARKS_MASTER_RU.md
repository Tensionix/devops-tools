# Browser Bookmarks Master

`Browser Bookmarks Master` - раздел OS -> Браузеры для управляемого экспорта и импорта эталона закладок Chromium-браузеров.

Он поддерживает два явных источника импорта:

- обычный HTML-export `.html`/`.htm` — основной clean-import `Bookmarks` и встроенных `ICON=`;
- нативную backup-папку профиля — аварийный путь восстановления готовых `Bookmarks` и `Favicons`.

Нативный backup работает с живыми файлами профиля:

- `Bookmarks` - JSON-структура закладок;
- `Favicons` - SQLite cache иконок;
- `Favicons-journal` - журнал SQLite для целостности базы.

## Главное Правило

Браузер должен быть закрыт перед копированием. По умолчанию GUI сам завершает процесс выбранного браузера или выбранных браузеров через `Close browser before file operation`. Это нужно, чтобы не копировать заблокированную или недописанную SQLite-базу `Favicons`.

Отключать этот чекбокс стоит только в expert-сценарии, когда процесс точно остановлен другим способом.

## Workbench-Маршрут

Пути задаются через Workbench:

- `TARGET` - куда экспортировать новый эталон;
- `SOURCE` - откуда импортировать эталон;
- `Status` показывает оба пути и пытается найти последний импортируемый backup в `SOURCE`.

Можно использовать локальные папки, внешние диски и UNC-пути вида `\\SERVER\Share\Folder`, если текущий Windows-сеанс уже имеет доступ к этой SMB-папке.

В GUI внутри `Browser Bookmarks Master` есть UNC-конструктор для `SOURCE` и `TARGET`. Он разбивает сетевой путь на три поля:

- `Имя сервера/компьютера` - например `NAS`, `OFFICE-PC` или `192.168.1.10`;
- `Share` - имя опубликованной общей папки;
- `Папка внутри Share` - необязательная подпапка, например `BrowserBackups`.

Слэши `\\` и `\` уже стоят в интерфейсе. Итоговый путь получается вида `\\SERVER\Share\Folder`.

## Версионирование Папок

Версионируются только папки backup.

Имя папки строится так:

```text
YYYY-MM-DD_HH-MM-SS_<backup_label>_vNN
```

Пример:

```text
2026-06-24_05-26-38_bookmarks_master_v01
```

`backup_label` задаёт понятное имя в середине папки. `backup_version` задаёт суффикс:

- пусто, `auto` или `next` - выбрать следующий свободный `vNN`;
- `1`, `01` или `v01` - начать с `v01`;
- если такая папка уже есть, операция не перезаписывает её, а поднимает номер до следующего свободного.

## Имена Файлов Внутри

Файлы внутри backup-папки остаются каноническими:

```text
Bookmarks
Favicons
Favicons-journal
```

Префиксы дат и суффиксы версий к ним не добавляются. Это важно: такие файлы можно напрямую положить обратно в профиль Chromium-браузера.

Дополнительно рядом создаётся служебный sidecar:

```text
audion_browser_bookmarks_manifest.json
```

Он нужен только Audion DevOps Tools для аудита: какой браузер, профиль, источник и версия были использованы.

## Операции

GUI устроен как action-switcher:

- `Status` - браузеры выбираются чекбоксами; можно проверить один или несколько профилей сразу.
- `Import` - в системном режиме браузеры выбираются чекбоксами и обрабатываются пакетом; portable-режим работает с одним точным профилем.
- `Export` - браузеры-источники выбираются чекбоксами; можно снять эталон сразу с нескольких Chromium-профилей.
- `Transfer` - источник выбирается radio-кнопкой, приёмники чекбоксами; браузер-источник скрывается из списка приёмников.
- `Открыть backup` - открывает project-local safety backup-папку.

Переключатели операций сделаны широкими кнопками с отчётливым активным состоянием. Цвет помогает навигации, но не заменяет `kind`, `risk_level`, подтверждение и журнал.

Если среди выбранных браузеров нет живого профиля, операция не падает целиком: такой браузер попадает в `SKIP`, GUI показывает жёлтое предупреждение, а остальные выбранные профили обрабатываются дальше.

`Status` ничего не меняет. Показывает выбранный браузер или выбранные браузеры, процесс, папку профиля, наличие трёх файлов, Workbench SOURCE/TARGET и последний импортируемый backup.

`Clear local Favicons cache` сохранён как service-mode для совместимости и закрывает браузер, затем удаляет только:

```text
Favicons
Favicons-journal
```

`Bookmarks` не трогается. При следующем запуске браузер создаст новый favicon-cache.

Отдельная команда `Очистить Favicons` доступна для всех отмеченных системных браузеров и одного portable-профиля. Rollback управляется одноимённым чекбоксом, включённым по умолчанию. Использовать команду следует только как полный reset: Chromium возвращает удалённые иконки лениво, по мере посещения сайтов.

`Export master to Workbench TARGET` закрывает выбранные браузеры, проверяет наличие всех трёх файлов и копирует их в новые версионированные папки под `TARGET`. При мульти-экспорте и заданном `backup_label` к имени папки добавляется ключ браузера, например `bookmarks_master_chrome`, `bookmarks_master_edge`, `bookmarks_master_brave`.

`Import master from Workbench SOURCE` показывает найденные в `SOURCE` нативные backup-папки списком: нужная папка выбирается явно. Скрытого выбора «самой новой» папки в GUI нет.

В режиме `HTML-файл` отдельная кнопка выбирает экспорт закладок. Это главный clean-import сценарий: старое дерево `Bookmarks` заменяется, favicon-таблицы очищаются и сразу заполняются встроенными `ICON=data:image/...` из HTML. Затем выполняются JSON- и SQLite-проверки. Перед импортом каждый отмеченный браузер закрывается и получает локальный pre-import backup в:

```text
backup\browser_bookmarks
```

Чекбокс `Создать rollback` включён по умолчанию и управляет страховочной копией для импорта и отдельной очистки Favicons. Если текущая favicon-база уже повреждена и сохранять её бессмысленно, чекбокс можно снять. Кнопка `Открыть backup` только открывает эту project-local папку и сама ничего не копирует.

Затем заменяет активные файлы профиля из выбранного эталона.

Переключатель `СИСТЕМНЫЙ / PORTABLE` определяет способ поиска профиля. Системный режим использует стандартные пути Chrome/Edge/Brave/Vivaldi и других известных браузеров. В portable-режиме нужно выбрать точную папку профиля, содержащую `Bookmarks`; папки с `chrome.exe` недостаточно, поскольку portable-сборка может задавать произвольный `--user-data-dir`.

`Transfer master between browsers` не использует Workbench SOURCE/TARGET. Он делает два служебных этапа через project-local backup:

1. Закрывает браузер-источник и выгружает его `Bookmarks`, `Favicons`, `Favicons-journal` в `backup\browser_bookmarks`.
2. Для каждого браузера-приёмника закрывает процесс, делает pre-import backup, очищает локальный `Favicons`/`Favicons-journal` и импортирует промежуточный эталон.

Это быстрый сценарий “Chrome -> всё остальное” или “Vivaldi -> выбранные Chromium-браузеры” без облачного merge.

`Открыть backup` открывает project-local папку safety backups, куда складываются pre-import снимки; сама кнопка backup не создаёт.

## Поддерживаемые Профили

Встроенные профили:

- Google Chrome;
- Microsoft Edge;
- Brave Browser;
- Vivaldi;
- Yandex Browser;
- Opera Stable.

Для нестандартного профиля используй `Profile path override`. Это должна быть точная папка профиля, например:

```text
%LOCALAPPDATA%\Google\Chrome\User Data\Profile 1
```

## Безопасный Ритуал

Экспорт эталона:

1. Открыть Workbench `TARGET` на нужную backup-папку или сетевой share.
2. Выбрать один или несколько браузеров чекбоксами.
3. Задать `Backup label`, например `audion_base`.
4. Оставить `Backup version = auto`.
5. Запустить `Status`.
6. Запустить `Export master to Workbench TARGET`.

Импорт эталона:

1. Открыть Workbench `SOURCE` на папку, где лежат versioned backup-папки.
2. В системном режиме отметить один или несколько браузеров чекбоксами. В portable-режиме выбрать один браузер radio-кнопкой и точную папку его профиля.
3. Запустить `Status` и проверить найденный backup.
4. Запустить `Import master from Workbench SOURCE`. Для HTML выполняется чистая пересборка `Bookmarks` и favicon-базы из встроенных ICON; для нативного backup копируется готовый комплект профиля.
5. Операция оставляет браузеры закрытыми. Программа не запускает их автоматически.
5. Запустить браузер вручную и проверить закладки/иконки до включения синхронизации.

Перенос между браузерами:

1. Выбрать `Transfer`.
2. Выбрать браузер-источник radio-кнопкой.
3. Отметить браузеры-приёмники чекбоксами; источник в приёмниках не показывается.
4. Оставить `Backup version = auto`.
5. Запустить `Transfer master between browsers`.
6. Проверить приёмники вручную до включения синхронизации.

Если синхронизация нужна, включай её только после проверки локального состояния.
