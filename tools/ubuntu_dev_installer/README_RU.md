# Ubuntu Dev/Create Installer Kit v4

Этот релиз сохраняет ту же идею слоистого установщика, но делает путь первого дня более консервативным и более понятным.

Что изменилось в v4:

- цветной вывод меню для более удобного чтения в реальном терминале;
- dry-run preview для профилей и dry-run preview для отдельных слоёв;
- профиль `Minimal` стал строже и больше не подтягивает опциональные дополнения автоматически;
- `ubuntu-restricted-extras` вынесен из базового слоя в отдельный опциональный официальный слой;
- README теперь рассматривает этот набор как стартовую архитектуру portable NVMe-Linux, а не просто как shell-обёртку.

---

## 1. Основная идея

Цель не в том, чтобы обрушить на машину одну гигантскую команду `apt install ...`.

Цель в том, чтобы:

- ставить систему слоями;
- проверять железо между слоями;
- делать снапшоты между осмысленными контрольными точками;
- держать пути в живой системе короткими и нейтральными;
- оставлять более рискованные или более субъективные части на потом.

Это особенно полезно, когда ты ещё только нарабатываешь мышечную память под Linux и хочешь первую систему без лишней драмы.

---

## 2. Философия portable NVMe-Linux

Это не магическое обещание формата «воткнул SSD куда угодно — и всё идеально работает».

Это практичная схема системы и пакетного workflow, задуманная так, чтобы установку Linux на ноутбук было легче:

- понимать;
- обслуживать;
- откатывать;
- концептуально переносить между машинами.

Рекомендуемая базовая схема для SSD на 256 ГБ:

- EFI: 512 МБ, FAT32
- один основной раздел Btrfs под систему
- подтома:
  - `@`, смонтированный в `/`
  - `@home`, смонтированный в `/home`

Если гибернация не нужна, стартовую схему лучше держать простой, а вопрос swap решить позже.

---

## 3. Держим пути короткими

Брендинг используй в документации, названиях релизов и проектных наборах.

Внутри живой системы пути лучше держать нейтральными и короткими.

Рекомендуемые папки:

- `~/Terminal`
- `~/Projects`
- `~/Apps`
- `~/Sync`
- `~/Media`
- `~/Vault`
- `~/Lab`

Так система остаётся чище, а перенос между машинами — проще.

## 4. Модель профилей

### Minimal

Консервативная Ubuntu-first-конфигурация.

Включает:

- Base
- Hardware / Intel / Wi-Fi / Bluetooth / color basics
- Terminal
- Sync
- Media Minimal
- опциональный шаг NVIDIA после стабилизации железа

Именно с этого и стоит начинать.

### Full

Всё из Minimal, плюс:

- Optional official Ubuntu extras
- Media Full
- Create Full

Это профиль «комфортная рабочая станция».

### Lab

Всё из Full, плюс:

- Lab / experimental layer

Используй его, когда ты уже осознанно хочешь тестировать контейнеры, AI-инструменты или другие не совсем базовые вещи.

## 5. Назначение слоёв

### Base

Базовые инструменты для storage, шифрования, recovery и rollback.

Сюда входят:

- Btrfs tools
- cryptsetup
- утилиты GPT / EFI
- zstd
- Timeshift
- rsync / curl / wget

Специально больше не входят:

- `ubuntu-restricted-extras`
- опциональные desktop-дополнения, которые могут создать лишнее трение при первом чистом запуске

### Hardware / Intel

Это слой, на котором стабилизируется:

- база Intel graphics / VA-API
- поддержка Wi‑Fi и Bluetooth
- firmware и утилиты диагностики
- базовые пакеты управления цветом

Важно:

- поддержка AX200 / AX211 в Linux — это обычно история про `iwlwifi` + `linux-firmware`, а не про скачивание какого-то vendor `.run`-драйвера;
- LUT / ICC workflow нужно трогать **после** того, как система уже стабильно живёт с графикой, сном, пробуждением и сетью.

### NVIDIA step

Этот шаг специально вынесен отдельно.

Скрипт использует:

```bash
sudo ubuntu-drivers install
```

Почему:

- Ubuntu сама может безопаснее выбрать рекомендуемую ветку, чем жёстко прибитый номер пакета в универсальном скрипте;
- роль играют Secure Boot, состояние ядра и различия между релизами.

### Terminal

Базовый day-one CLI и dev-слой:

- `micro`
- `mc`
- `neovim`
- `git`
- `ripgrep`
- `fd-find`
- компиляторы
- Python
- `tmux`
- `fzf`
- `shellcheck`

### Sync

Инфраструктурный слой:

- Syncthing
- rclone
- SSH
- WireGuard
- сетевые утилиты

### Media Minimal

Базовое воспроизведение и инспекция в первый день:

- `ffmpeg`
- `mpv`
- `vlc`
- `smplayer`
- `mediainfo`
- музыкальные плееры

### Optional official Ubuntu extras

Этот слой существует потому, что некоторые вещи всё ещё полезны, но не должны неожиданно вмешиваться в первый запуск.

Примеры:

- `flatpak`
- `ubuntu-restricted-extras`

Важно:

- `ubuntu-restricted-extras` в зависимости от релиза и состояния пакетов может требовать интерактивного участия;
- именно поэтому он больше не спрятан в базовом слое.

### Media Full

Более тяжёлый медиаслой, например:

- HandBrake
- MKVToolNix
- ImageMagick
- SoX
- tagging / audio tools

### Create Full

Более широкий creator / analysis-слой:

- Audacity
- OBS Studio
- VapourSynth
- Gifski
- metadata helpers
- routing utilities

### Lab

Именно сюда должна уходить экспериментальная часть:

- Podman
- Distrobox
- Ollama

Относись к этому как к опциональному и обратимому слою, а не как к священной части базовой системы.

## 6. Dry-run mode

В v4 добавлены preview-режимы.

Теперь можно просматривать заранее:

- профиль Minimal
- профиль Full
- профиль Lab
- выбранные слои
- транзакции удаления

Это полезно, если ты хочешь сначала увидеть, что именно Ubuntu собирается сделать, прежде чем подтверждать установку.

Для preview скрипт использует `apt-get -s`.

---

## 7. Внешние / ручные установки

Некоторые приложения специально не проталкиваются через установщик.

Почему:

- для них может быть лучше Flatpak / AppImage / upstream-бинарник;
- это могут быть инструменты личного вкуса;
- они могут быстро меняться или зависеть от одного внешнего мейнтейнера.

Смотри:

- `packages/external_apps_manual.txt`

Типичные примеры:

- Shutter Encoder
- LosslessCut
- DisplayCAL
- и другие инструменты, доступные только upstream или поддерживаемые вручную

---

## 8. Рекомендуемый первый проход

Рекомендуемый порядок для свежей системы:

1. Установить профиль Minimal
2. Проверить:
   - дисплей
   - звук
   - сон / пробуждение
   - Wi‑Fi / Bluetooth
   - тачпад / клавиатуру
3. Выполнить отдельный шаг NVIDIA
4. Создать снапшот Timeshift
5. Выборочно установить части профиля Full
6. И только после этого лезть в Lab

Так кривая обучения остаётся под контролем.

---

## 9. Статус smoke-test

Shell-логика была проверена в sandbox с подменными `sudo`, `apt-get`, `apt-cache` и `ubuntu-drivers`.

Что было подтверждено:

- синтаксис `bash -n`
- работа меню
- работа dry-run
- разрешение слоёв
- ветвление Y / N / Q
- вход в NVIDIA step
- корректный пропуск пакетов, если пакет недоступен

Что не было полноценно подтверждено в sandbox:

- реальные установки пакетов на живой Ubuntu desktop;
- взаимодействие с Secure Boot;
- фактический выбор ветки NVIDIA;
- реальное поведение сна / пробуждения / ICC / LUT на физическом железе.

## 11. Практическое правило

Брендинг — для релиза.

Живая система — чистая.

То есть:

- название набора может быть брендовым;
- документация может быть брендовой;
- реальные пути в файловой системе должны оставаться короткими и нейтральными.
