# Btrfs + Timeshift для Ubuntu: отдельный storage-guide

Этот документ специально отделён от DevOps/Package-Install слоя.

Здесь только:
- выбор целевого SSD/NVMe;
- GPT + EFI + Btrfs;
- подтома `@` и `@home`;
- смысл mount options;
- когда это делать из Live-USB, а когда уже поздно и больно.

---

## 1. Что отделяем от "суперкомбайна"

### Отдельно живёт:
- **Storage layer**
  - GPT
  - EFI
  - Btrfs
  - subvolumes
  - mount options
  - Timeshift

### Отдельно живёт:
- **DevOps / Install layer**
  - пакеты
  - NVIDIA step
  - terminal/dev/media layers
  - baseline directories (`~/Terminal`, `~/Projects`, `~/Apps`, `~/Sync`, `~/Media`, `~/Vault`, `~/Lab`)

Это правильно, потому что storage — это фундамент. Пакеты и профили можно откатить или переставить. Разметка диска и корневой layout — намного более базовый слой.

---

## 2. Минимальная схема под твой сценарий

Для SSD 256 ГБ разумно начать максимально просто:

- **EFI System Partition** — 512 MiB, FAT32
- **Btrfs partition** — всё остальное

Внутри Btrfs:

- `@` → `/`
- `@home` → `/home`

И всё.

Без `@var`, `@snapshots`, `@cache`, `@docker` на первом проходе.

---

## 3. Почему именно так

### `subvol=@` или `subvol=@home`
Это указание, **какой именно Btrfs subvolume монтировать**.

Если монтируешь `subvol=@`, система видит этот подтом как `/`.

Если монтируешь `subvol=@home`, система видит этот подтом как `/home`.

### `compress=zstd`
Это прозрачное сжатие Btrfs.

Почему это хорошо:
- современный быстрый алгоритм;
- часто реально экономит место;
- обычно не мешает нормальной desktop-работе.

### `noatime`
Отключает постоянное обновление access time при каждом чтении файла.

Практический смысл:
- меньше лишних записей;
- чуть меньше мусорной активности на SSD/NVMe.

---

## 4. Когда делать это лучше всего

### Лучший момент
**До установки Ubuntu, из Live-USB.**

Это самый чистый и понятный путь.

### Почему не после
Потому что после установки придётся:
- мигрировать уже установленный root;
- копировать систему между подтомами;
- править `fstab`;
- следить за EFI, initramfs и grub;
- легко словить ненужную путаницу.

То есть "после" — можно, но это уже не стартовый сценарий, а rescue/repair task.

---

## 5. Рекомендуемый рабочий порядок

1. Загружаешься с Ubuntu Live-USB.
2. Проверяешь, какой диск целевой.
3. Запускаешь prep-script.
4. Скрипт:
   - стирает диск;
   - создаёт GPT;
   - создаёт EFI + Btrfs;
   - создаёт `@` и `@home`;
   - монтирует всё под `/mnt`.
5. После этого запускаешь установщик Ubuntu.
6. В установщике идёшь в ручную разметку (`Something else`).
7. Используешь уже подготовленные разделы и mount points.
8. После установки ставишь Timeshift.

---

## 6. Что делает приложенный prep-script

Файл:

`Ubuntu_Btrfs_LU_Prep_NVMe.sh`

Он делает следующее:

- показывает доступные диски;
- даёт выбрать целевой SSD/NVMe;
- требует typed confirmation;
- удаляет старую разметку;
- создаёт:
  - EFI 512 MiB;
  - Btrfs-раздел на остальное;
- форматирует:
  - EFI → FAT32;
  - data → Btrfs;
- создаёт subvolumes:
  - `@`
  - `@home`
- монтирует:
  - `@` → `/mnt`
  - `@home` → `/mnt/home`
  - EFI → `/mnt/boot/efi`

Скрипт **не ставит Ubuntu сам**. Это сознательно.

Так безопаснее, прозрачнее и проще отлаживать.

---

## 7. Почему установку лучше оставить ручной

Потому что автоматизировать именно **разметку и mount layer** — полезно.

А автоматизировать ещё и весь install flow сразу — уже опаснее.

Особенно когда:
- ещё нет финального живого Linux на руках;
- есть разное железо;
- возможны отличия установщика Ubuntu 26 LTS.

То есть правильная граница такая:

- **prep-script** → готовит диск и mount targets;
- **Ubuntu installer** → ставит систему;
- **post-install installer kit** → ставит пакеты, baseline, NVIDIA и остальное.

---

## 8. Timeshift после установки

После установки Ubuntu:

```bash
sudo apt update

sudo apt install timeshift
```

Дальше запускаешь Timeshift и выбираешь режим **BTRFS**.

Что я рекомендую на старте:
- снапшоты root-системы;
- `@home` в откат сразу не тащить;
- график умеренный:
  - Daily: 3
  - Weekly: 2
  - Monthly: 1

Ручные снапшоты делать:
- перед NVIDIA;
- перед крупным upgrade;
- перед LUT/ICC;
- перед экспериментами с boot/fstab.

---

## 9. Что НЕ делать на первом проходе

Не надо сразу:
- делать 10 подтомов;
- добавлять отдельный `@snapshots` ради красоты;
- лезть в post-install migration из ext4/Btrfs root в новый layout;
- смешивать disk-prep и package-install в один монолит.

Цель первого цикла — **чистый рабочий старт**, а не максимальная "архитектурная победа за один вечер".

---

## 10. Практический итог

Для тебя логика должна быть такой:

### Phase 1 — Live-USB storage prep
- GPT
- EFI 512 MiB
- Btrfs
- `@`
- `@home`

### Phase 2 — Ubuntu install
- ручная разметка / Something else
- reuse готовых разделов

### Phase 3 — Post-install
- Timeshift
- init directories
- Minimal / Full / Lab packages
- NVIDIA / media / dev layers

Это и есть самый спокойный, понятный и расширяемый старт.
