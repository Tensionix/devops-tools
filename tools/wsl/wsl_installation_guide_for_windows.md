# WSL на Windows — подробный практический гайд

## 1. Что такое WSL и где чаще всего возникает путаница

WSL — это не Ubuntu и не Linux-дистрибутив.

WSL — это слой совместимости и виртуализации в Windows, который позволяет запускать Linux-дистрибутивы.

Ubuntu, Debian и другие системы внутри WSL — это уже отдельные дистрибутивы, которые устанавливаются поверх готовой платформы WSL.

Из-за этого одна и та же команда `wsl --install` может восприниматься двояко:

- как установка самой платформы WSL;
- как установка WSL вместе с Ubuntu по умолчанию.

На практике обе трактовки частично верны, потому что это комбинированная команда.

---

## 2. Логика установки: платформа и дистрибутив — это разные вещи

Есть два отдельных слоя:

### Слой 1. Платформа WSL
Это компоненты Windows, которые делают возможным запуск WSL.

### Слой 2. Linux-дистрибутив
Это уже Ubuntu, Debian, openSUSE и так далее.

Поэтому важно разделять четыре разных действия:

1. установить сам WSL;
2. установить конкретный дистрибутив;
3. обновить платформу WSL;
4. обновить пакеты внутри самого Linux-дистрибутива.

---

## 3. Что делает `wsl --install`

### Вариант без параметров

```powershell
wsl --install
```

Обычно эта команда:

- включает необходимые компоненты Windows;
- устанавливает платформу WSL;
- устанавливает Ubuntu по умолчанию.

Это удобный сценарий для быстрого старта.

### Вариант с конкретным дистрибутивом

```powershell
wsl --install -d Ubuntu-24.04
```

или

```powershell
wsl --install -d Debian
```

Этот вариант:

- ставит WSL, если он ещё не установлен;
- ставит выбранный дистрибутив вместо использования дефолтного сценария.

Именно поэтому отдельный предварительный `wsl --install` без параметров не обязателен.

---

## 4. Можно ли на чистой системе сразу поставить конкретный дистрибутив

Да, можно.

Например:

```powershell
wsl --install -d Ubuntu
```

или:

```powershell
wsl --install -d Ubuntu-24.04
```

Это нормальный сценарий даже на полностью новой системе.

Отдельно ставить сначала «пустой WSL», а потом дистрибутив — не обязательно.

---

## 5. Можно ли сразу указать своё место установки

Да, можно.

Например:

```powershell
wsl --install -d Ubuntu --location "S:\WSL\VHDX\Ubuntu"
```

или:

```powershell
wsl --install -d Ubuntu-24.04 --location "S:\WSL\VHDX\Ubuntu-24.04"
```

Это означает:

- если WSL ещё не установлен, он будет подготовлен;
- выбранный дистрибутив установится в указанную папку.

Это как раз хороший сценарий для тех, кто не хочет держать дистрибутив на системном диске `C:`.

---

## 6. Как поставить только платформу WSL без дистрибутива

Если ты хочешь сначала подготовить только саму платформу, а дистрибутив выбрать потом вручную, используй:

```powershell
wsl --install --no-distribution
```

После этого можно отдельно посмотреть доступные дистрибутивы:

```powershell
wsl --list --online
```

И затем установить нужный:

```powershell
wsl --install -d Ubuntu --location "S:\WSL\VHDX\Ubuntu"
```

Такой сценарий особенно хорош, если ты хочешь полный контроль над тем, что именно ставится и куда.

---

## 7. Когда стоит использовать `wsl --import`

Есть ещё один путь — импорт готового tar/vhd-образа:

```powershell
wsl --import MyUbuntu "S:\WSL\VHDX\MyUbuntu" .\ubuntu.tar
```

Это не обычная установка из официального списка дистрибутивов, а ручной импорт.

Этот сценарий полезен, когда:

- у тебя уже есть подготовленный rootfs-архив;
- ты переносишь дистрибутив между системами;
- тебе нужен максимально ручной и контролируемый способ развертывания.

Для обычной установки Ubuntu или Debian проще и удобнее использовать `wsl --install -d ...`.

---

## 8. Как посмотреть, что вообще доступно для установки

Команда:

```powershell
wsl --list --online
```

показывает список дистрибутивов, которые доступны для установки через WSL.

После этого можно выбрать нужный вариант.

Примеры:

```powershell
wsl --install -d Ubuntu
```

```powershell
wsl --install -d Ubuntu-24.04
```

```powershell
wsl --install -d Debian
```

---

## 9. Обновляется ли WSL командой `wsl --install`

Не в том смысле, в котором обычно говорят «обновить WSL».

Для обновления самой платформы WSL используется:

```powershell
wsl --update
```

Для просмотра состояния:

```powershell
wsl --status
```

Для просмотра версии:

```powershell
wsl --version
```

То есть:

- `wsl --install` — установка;
- `wsl --update` — обновление платформы WSL.

---

## 10. Обновление Ubuntu внутри WSL — это уже другая история

После первого запуска Ubuntu внутри WSL ты обновляешь уже не WSL, а сам Linux.

Команды внутри Ubuntu:

```bash
sudo apt update

sudo apt upgrade -y
```

При необходимости:

```bash
sudo apt full-upgrade -y
```

И очистка ненужных пакетов:

```bash
sudo apt autoremove -y
```

Важно понимать разницу:

- `wsl --update` обновляет платформу WSL в Windows;
- `apt update` и `apt upgrade` обновляют Ubuntu внутри WSL.

wsl --install --no-distribution

## 13. Важные замечания

### 1. Не путай WSL и Ubuntu
WSL — это платформа.
Ubuntu — это дистрибутив внутри неё.

### 2. `wsl --install` не означает обязательную установку только Ubuntu
Если задать `-d`, ставится выбранный дистрибутив.

### 3. `wsl --install` и `wsl --update` — разные вещи
Первая команда ставит, вторая обновляет.

### 4. `--location` особенно полезен на системах с маленьким `C:`
Это хороший способ держать WSL на отдельном SSD.

### 5. Обновление Ubuntu делается уже внутри самой Ubuntu
Это обычные `apt`-команды, а не `wsl --update`.

---

## 14. Краткое резюме

Самая простая формула такая:

- `wsl --install` — поставить WSL и обычно Ubuntu по умолчанию;
- `wsl --install -d <name>` — поставить WSL и конкретный дистрибутив;
- `wsl --install --no-distribution` — поставить только платформу WSL;
- `wsl --install -d <name> --location "..."` — поставить выбранный дистрибутив в нужную папку;
- `wsl --update` — обновить сам WSL;
- `sudo apt update && sudo apt upgrade -y` — обновить Ubuntu внутри WSL.
